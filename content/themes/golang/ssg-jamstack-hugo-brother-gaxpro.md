### What You Need Before You Start

Before you begin, make sure you have these on your computer:

- **Go 1.26 or newer** — the build runtime. Free download from go.dev/dl.
- **A text editor** — VS Code, Sublime Text, or any editor that handles Markdown files. Notepad works, but VS Code is easier.

**A note on the terminal**

The terminal is a text window where you type commands. On Windows, open **Command Prompt** from the Start menu, or **PowerShell** if you prefer. On macOS, open **Terminal** from Applications > Utilities. On Linux, open your terminal app.

Every command in this guide is typed into the terminal, then you press Enter to run it. Commands are shown in a box like this:

```
go version
```

Copy the command, paste it into the terminal, press Enter.

### Step 2: Installation

This step installs Go and builds the GAX binary. It is done once.

**Install Go**

Windows:

1. Go to go.dev/dl
2. Download the Windows installer (`.msi`) for the latest version.
3. Run the installer and follow the default prompts.
4. Go installs to `C:\Program Files\Go` and adds itself to your PATH automatically.

macOS:

1. Go to go.dev/dl
2. Download the macOS installer (`.pkg`).
3. Run the installer and follow the default prompts.

Or, if you use Homebrew:

```
brew install go
```

Linux:

For Debian or Ubuntu:

```
sudo apt update
sudo apt install golang-go
```

For Fedora:

```
sudo dnf install golang
```

For Arch:

```
sudo pacman -S go
```

Or download the official binary from go.dev/dl and add Go to your PATH.

**Verify the installation**

Open a terminal and run:

```
go version
```

You should see something like `go version go1.26.0 windows/amd64`. If you see "command not found" or "not recognized", Go is not in your PATH. Reinstall using the official installer, or add the Go binary directory to your PATH manually.

**Build the GAX binary**

1. Open a terminal.
2. Go to the project folder:

```
cd path/to/gaxpro
```

On Windows, the path looks like:

```
cd C:\Users\YourName\Desktop\gaxpro
```

3. Build the binary:

```
go build -o gax ./cmd/gax
```

On Windows, this creates `gax.exe`. On macOS and Linux, this creates `gax`. You only need to build once. After that, you run the binary directly.

### Step 3: Run the Project

Development mode starts a local server with live reload. Every time you save a file, the browser refreshes.

1. Open a terminal in the project folder.
2. Run:

```
./gax
```

On Windows:

```
gax.exe
```

3. Open your browser and go to:

```
http://localhost:8080
```

You should see the GAX Pro homepage. The server is now running.

**What you see**

The homepage shows the theme's landing page: hero section, features, pricing, FAQ, and call-to-action. This is the starter content that ships with the theme. You will edit this later.

**Live reload**

While the server is running, open any file in the `content/` folder, make a change, and save it. The browser refreshes automatically. This is the development workflow.

**Stop the server**

Press `Ctrl + C` in the terminal to stop the server.

### Step 4: Run the Project with Decap CMS

Decap CMS is a browser-based editing interface. It lets you edit content in a clean UI instead of editing Markdown files directly.

This step is optional. If you are comfortable editing Markdown files, skip to Step 5. If you want browser-based editing, follow this step.

**What Decap CMS adds**

- A clean editing interface at `http://localhost:8080/admin/`
- Form fields for title, description, date, tags, and body
- No need to remember frontmatter syntax
- A preview of how the content will look

**Open two terminals**

Decap CMS needs two processes running at the same time:

1. **The GAX development server** — serves the site at `http://localhost:8080`
2. **The Decap CMS proxy** — lets the CMS write files back to your local project

That is why you open two terminals: one for the site, one for the CMS proxy.

**Terminal 1: Run the GAX project**

```
cd path/to/gaxpro
./gax
```

On Windows:

```
cd C:\Users\YourName\Desktop\gaxpro
gax.exe
```

Leave this terminal running. The site is now live at `http://localhost:8080`.

**Terminal 2: Run the Decap CMS proxy**

Open a second terminal. Go into the same project folder:

```
cd path/to/gaxpro
```

Run the Decap CMS proxy:

```
npx decap-server
```

This requires Node.js. If you do not have Node.js, install it from nodejs.org. The proxy starts and listens for the CMS. Leave this terminal running too.

**Open the CMS**

With both terminals running, open:

```
http://localhost:8080/admin/
```

The Decap CMS login screen appears. Because you are running with the local backend, the login is automatic — the CMS checks that the local proxy is running and connects to it.

If the login fails:

- Check that `npx decap-server` is running in Terminal 2
- Check that `./gax` is running in Terminal 1
- Check that `local_backend: true` is set in `public/admin/config.yml`
- Reload the page after both terminals are confirmed running

**What you can edit in the CMS**

Once logged in, the left sidebar shows the content types:

- **Pages** — homepage, about, contact, 404, tags
- **Blog** — blog articles
- **Services** — service pages
- **Projects** — project pages
- **Docs** — documentation pages
- **Site Config** — navigation, footer, brand, social links

Click a content type to see its entries. Click **New** to create a new entry, or click an existing entry to edit it.

**Editing the homepage**

The homepage is a single file at `content/index.md`. In the CMS, it appears under **Pages > Homepage**. The form shows the frontmatter fields as form inputs: hero title, lead text, primary button, and so on. Edit the fields, then click **Save** or **Publish**.

The CMS writes the changes back to `content/index.md`. The site rebuilds on the next request, and the browser shows the updated homepage after a refresh.

**Adding a blog article**

1. Open **Blog** in the CMS sidebar
2. Click **New**
3. Fill in the frontmatter fields: title, description, date, tags, image
4. Write the body in the Markdown editor
5. Click **Publish**

The CMS creates a new Markdown file in `content/blog/`. GAX adds it to the collection on the next build.

**Editing the site configuration**

The `_data/config.yaml` file holds site-wide settings. In the CMS, it appears under **Site Config**. Edit the site title, navigation, footer, social links, and widgets. Save the file and the changes appear on every page.

**Switching between CMS and text editor**

Both workflows edit the same files. You can switch between them freely:

- Edit a file in the CMS, then open it in a text editor to see the same content
- Edit a file in a text editor, then reload the CMS to see the change

There is no lock-in. The CMS is a convenience layer over the Markdown files.

**Decap CMS errors**

**CMS shows a blank screen** — the local proxy is not running, or `local_backend` is not set. Check Terminal 2 and `config.yml`.

**Login does not complete** — the proxy is running but the CMS cannot reach it. Check that the port matches (default `8081` for the proxy, `8080` for the site).

**Changes do not save** — the proxy is not running, or the file path in `config.yml` is wrong.

**New article does not appear** — the CMS saved the file but GAX did not rebuild. Reload the site or restart `./gax`.

### Step 6: Deploy to Production

This step covers the full deployment path: pushing to GitHub, connecting a host, and running the deploy. It also covers Decap CMS production setup.

**Deploy prerequisites**

- A GitHub account
- A hosting account (Netlify is recommended for Decap CMS)
- Git installed on your computer

Git is separate from Go. On Windows, install it from git-scm.com. On macOS, it comes with the Xcode Command Line Tools. On Linux, install it through your package manager.

**Step 6.1: Create a GitHub repository**

1. Go to github.com and sign in (or sign up if you do not have an account)
2. Click the **+** icon in the top right, then **New repository**
3. Name the repository — for example, `gaxpro-site`
4. Choose **Private** or **Public**
5. Do **not** initialize with a README, `.gitignore`, or license — the project already has files
6. Click **Create repository**

GitHub shows the commands to connect an existing folder to this repository. Keep that page open.

**Step 6.2: Push the project to GitHub**

1. Open a terminal in the project folder:

```
cd path/to/gaxpro
```

2. Initialize Git if the folder is not already a repository:

```
git init
```

3. Add all files and commit:

```
git add .
git commit -m "Initial commit"
```

4. Connect the local repository to GitHub. Replace `yourusername` and `gaxpro-site` with your actual values:

```
git remote add origin https://github.com/yourusername/gaxpro-site.git
git branch -M main
git push -u origin main
```

5. After the push completes, refresh the GitHub repository page. The project files should be visible.

**Step 6.3: Deploy to Netlify (recommended for Decap CMS)**

Netlify is the recommended host if you want Decap CMS working on the live site. It provides Identity and Git Gateway, which handle authentication and Git commits on behalf of editors.

1. Go to app.netlify.com and sign up or log in
2. Click **Add new site**, then **Import an existing project**
3. Choose **GitHub** and authorize Netlify
4. Select the `gaxpro-site` repository
5. Configure the build settings:

| Setting | Value |
|---|---|
| Build command | `go build -o gax ./cmd/gax && ./gax build` |
| Publish directory | `site` |

6. Click **Deploy site**

Netlify runs the build on every push to `main`. The first deploy takes a few minutes. When it finishes, Netlify gives you a URL like `https://your-site.netlify.app`.

**Step 6.4: Enable Netlify Identity**

1. In the Netlify site dashboard, go to **Integrations** > **Identity**
2. Click **Enable Identity**
3. Under **Registration**, choose **Invite only** for a private site, or **Open** if you want anyone to sign up
4. Under **External providers**, you can enable Google or GitHub login if you want one-click sign-in

**Step 6.5: Enable Git Gateway**

1. In the same Identity section, scroll to **Services** > **Git Gateway**
2. Click **Enable Git Gateway**
3. Leave the **Roles** field blank to allow all Identity users access

Git Gateway connects Netlify Identity to your GitHub repository. When an editor logs in through the CMS, Git Gateway commits changes to the repository on their behalf. Editors do not need GitHub accounts or repository write access.

**Step 6.6: Configure Decap CMS for production**

Open `public/admin/config.yml` and set the backend to Git Gateway:

```yaml
backend:
  name: git-gateway
  branch: main
```

Remove the `local_backend` line if it exists. It is only used for local development with `npx decap-server`. In production, Git Gateway replaces it.

Commit the changes and push:

```
git add .
git commit -m "Configure Decap CMS for production"
git push
```

Netlify rebuilds the site. After the deploy finishes, open `https://your-site.netlify.app/admin/`. The CMS login page appears. Log in with the Netlify Identity account you invited, and the CMS loads.

**Step 6.7: Invite editors**

1. In the Netlify dashboard, go to **Identity**
2. Click **Invite users**
3. Enter the editor's email address
4. The editor receives an email with a link to set a password

Once they log in, they can edit content through `/admin/` without a GitHub account.

**Step 6.8: Deploy to Vercel**

Vercel is a strong host for static sites, but Decap CMS production setup is more involved. It requires an external OAuth proxy because Vercel does not provide a built-in Git Gateway.

1. Go to vercel.com and sign up or log in
2. Click **Add New** > **Project**
3. Import the GitHub repository
4. Set the build command and output directory:

| Setting | Value |
|---|---|
| Build command | `go build -o gax ./cmd/gax && ./gax build` |
| Output directory | `site` |

5. Click **Deploy**

Vercel builds on every push. The site gets a URL like `https://your-site.vercel.app`.

For Decap CMS on Vercel, you need to deploy a separate OAuth proxy. The steps are:

1. Create a GitHub OAuth App
2. Deploy an OAuth proxy (for example, a Cloudflare Worker or a Vercel function)
3. Set `backend.base_url` in `config.yml` to the proxy URL
4. Set `backend.name: github`

This is more setup than Netlify. If Decap CMS is a priority, use Netlify instead.

**Step 6.9: Deploy to Cloudflare Pages**

1. Go to the Cloudflare dashboard, then **Workers & Pages**
2. Click **Create application** > **Pages** > **Import an existing Git repository**

6. Click **Save and Deploy**

**Step 6.10: Deploy to GitHub Pages**

1. Push to GitHub (steps 6.1 and 6.2)
2. Add a workflow file to `.github/workflows/deploy.yml`
3. Configure the workflow to build with Go and upload the `site/` folder
4. Enable GitHub Pages in repository settings

Note: GitHub Pages free requires a public repository. Decap CMS on GitHub Pages requires an external OAuth proxy.

Point your web server (Nginx or Apache) to `/var/www/gaxpro/`.

For automated deploy, use an SSH deploy action in GitHub Actions. The project includes example workflows in `.github/workflows/`.

**Step 6.12: Deploy to cPanel**

### Step 8: Troubleshooting

**Build fails with "go: command not found"** — Go is not installed or not in your PATH. Reinstall from go.dev/dl.

**Build fails with "gax: command not found"** — the binary was not built. Run `go build -o gax ./cmd/gax` first.

**Port 8080 already in use** — another process is using the port. Close the other process or change the port in the GAX configuration.

**Site deploys but CSS is missing** — the asset paths in the theme are absolute. Make sure the `public/` folder was copied to the output. Check the host's publish directory setting.

**CMS shows "Failed to load config"** — the `config.yml` path is wrong. Check that `public/admin/config.yml` exists.

**Changes in the CMS do not save** — the Decap CMS proxy is not running. Check Terminal 2.

**CMS login fails on Netlify** — check that Identity is enabled, Git Gateway is enabled, and the Identity widget script is in `public/admin/index.html`.

**Changes in the CMS do not appear on the live site** — Netlify rebuilds on Git commits. Check that the commit reached the repository. If the build is slow, wait a minute and refresh.
