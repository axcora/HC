## ForgeDocs — All-in-One Astro Starlight Theme

If you have been looking for an Astro theme that does not force you to pick between a landing page, documentation, or a blog, ForgeDocs is worth a look. ## The Problem ForgeDocs Solves

Building a product site usually means stitching three separate things together:

1. A landing page template for marketing
2. A documentation framework for docs
3. A blog template for content

Each one comes with its own design system, its own navigation, its own deployment pipeline. You end up with three sites that do not look like they belong together, and three things to maintain.

ForgeDocs removes that problem. It combines all three into one Astro project with a shared design system and shared navigation. You deploy once. You maintain one codebase.

## Installation

This guide walks you through installing ForgeDocs on your local machine.

### Requirements

**Node.js 18 or newer**
Download the LTS version from https://nodejs.org

**A code editor**
Download VS Code from https://code.visualstudio.com

**A terminal**
Command Prompt on Windows, Terminal on macOS.

### Check Node.js

Open your terminal and run:

```bash
node --version
```

If you see `v18.0.0` or higher, you are ready. If not, install Node.js first.

### Step 1 — Download the Source Code

After purchase, download the ZIP file from your Gumroad library. Extract it to a folder on your computer.

Recommended location:

- Windows: `C:\Users\YourName\Desktop\forgedocs`
- macOS: `/Users/YourName/Desktop/forgedocs`

Avoid folders with spaces or special characters in the path.

### Step 2 — Open the Project in Terminal

**Windows:**

```cmd
cd C:\Users\YourName\Desktop\forgedocs
```

**macOS:**

```bash
cd ~/Desktop/forgedocs
```

Verify you are in the right folder:

- Windows: `dir`
- macOS: `ls`

You should see `package.json` in the list.

### Step 3 — Install Dependencies

```bash
npm install
```

This downloads all packages. It takes about 30–60 seconds the first time.

### Step 4 — Start the Development Server

```bash
npm run dev
```

Open your browser and go to:

```
http://localhost:4321
```

You should see the ForgeDocs homepage.

### Step 5 — Verify the Installation

```bash
npm run build
```

If the build completes without errors, you are ready.

### Troubleshooting

**`npm: command not found`** — Node.js is not installed. Reinstall from https://nodejs.org

**`EACCES: permission denied`** — On macOS or Linux, run `sudo npm install`

**`Module not found`** — Delete `node_modules` and `package-lock.json`, then run `npm install` again.

**Build fails with version errors** — Check `node --version`. Install the latest LTS if older than 18.

## Run Project

### Start the Development Server

```bash
npm run dev
```

Open `http://localhost:4321`.

The dev server watches your files. Changes appear instantly. Stop it with `Ctrl + C`.

### Build for Production

```bash
npm run build
```

This creates a `dist/` folder with your optimized site. Compiles all pages to static HTML, optimizes images, generates sitemap, and builds the Pagefind search index.

### Preview the Production Build

```bash
npm run preview
```

Serves the `dist/` folder locally. Use this to test the production build before deploying.

### The Three Commands

| Command | What it does |
|---|---|
| `npm run dev` | Development server at `localhost:4321` |
| `npm run build` | Build production site into `dist/` |
| `npm run preview` | Preview the production build locally |

## First Setup

### Edit astro.config.mjs

Open `astro.config.mjs` in your code editor. It is at the root of your project.

**Update `site` to your domain:**

```js
site: 'https://your-domain.com',
```

Astro uses this URL to generate canonical URLs and sitemap entries.

**Update Starlight title and description:**

```js
starlight({
  title: 'Your Site',
  description: 'Your description here.',
  ...
})
```

**Update the sidebar** to match your docs structure:

```js
sidebar: [
  {
    label: 'Getting Started',
    items: [
      { label: 'Welcome', slug: 'welcome' },
      { label: 'Installation', slug: 'getting-started/installation' },
    ],
  },
]
```

Save and restart the dev server.

## Update JSON Data

Most ForgeDocs content is stored in JSON files in `src/data/`.

### seo.json

Controls site-wide SEO metadata: title, description, keywords, Open Graph image, canonical URL, Twitter handle, favicon, theme colors.

### site.json

Site metadata: name, version, tagline, description, domain, demo URL, price, license.

### navbar.json

Navigation links and brand: logo, brand label, menu items, CTA button.

### footer.json

Footer columns, social links, copyright, legal links.

### home.json

Landing page content: hero, showcase, features, pricing plans, CTA section.

### features.json

Features page content: hero, stats, showcase, feature items with images.

### contact.json

Contact page: hero, Formspree ID, info items, highlights, form fields.

### blog.json

Blog labels: list title, pagination text, tag labels, SEO titles.

### JSON Rules

Always use double quotes. No trailing commas. Save with UTF-8 encoding. Test locally with `npm run dev`.

## Update Pages

### Docs Collection

Docs live in `src/content/docs/`. Each `.md` file becomes a page.

Frontmatter:

```md
---
title: Page Title
description: Short SEO description.
---

Content goes here in Markdown.
```

The sidebar is configured in `astro.config.mjs`.

### Blog

Blog posts live in `src/content/blog/`. Each `.md` file is a post.

Frontmatter:

```md
---
title: "Your Post Title"
description: "Short SEO description."
date: 2026-01-15
tags: [astro, tutorial]
image: /images/blog/cover.webp
imageAlt: "Cover description"
---

Content goes here.
```

### Static Pages

Static pages live in `src/content/pages/`. Each `.md` file becomes a page at `/{filename}/`.

Frontmatter:

```md
---
title: About
description: Short SEO description.
image: /images/about-hero.webp
imageAlt: "Image description"
layoutType: default
updated: 2026-01-15
---

Content goes here.
```

**Layout types:** `default`, `faq`, `legal`, `contact`.

If you bought the Code Only package, skip this section.

Decap CMS configuration lives in `public/admin/config.yml`. Verify the backend section:

```yaml
backend:
  name: git-gateway
  branch: main

local_backend: true

Decap CMS needs the production build to work. The dev server does not include the assets it needs.

```

## Push to GitHub

### Step 1 — Create a Repository

1. Go to [github.com/new](https://github.com/new)
2. Repository name: `forgedocs`
3. Do NOT add a README
4. Click **Create repository**

### Step 2 — Initialize and Push

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/forgedocs.git
git push -u origin main
```

You will be asked for a password. Use a **Personal Access Token**, not your GitHub password.

Create one at https://github.com/settings/tokens. Check the `repo` scope. Copy the token and paste it when Git asks for a password.

## Deploy to Netlify

### Step 1 — Connect Repository

1. Go to https://app.netlify.com/signup and sign up with GitHub
2. Click **Add new site** → **Import an existing project**
3. Select your `forgedocs` repository

### Step 2 — Build Settings

| Setting | Value |
|---|---|
| Branch | `main` |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node version | `20` |

Click **Deploy site**. Wait 1–3 minutes.

### Step 3 — Custom Domain (Optional)

Go to **Site configuration** → **Domain management** → **Add a domain**. Follow the DNS instructions. Netlify provides free HTTPS automatically.

### Step 4 — Enable Netlify Identity (For Decap CMS)

1. Go to **Identity** → **Enable Identity**
2. Under **Registration preferences**, choose **Invite only**
3. Go to **Identity** → **Services** → **Git Gateway** → **Enable Git Gateway**

### Step 5 — Invite Yourself

1. Go to **Identity** → **Invite users**
2. Enter your email
3. Click **Send**

Check your email, accept the invite, set a password.

### Step 6 — Access the CMS

Go to:

```
https://your-site.netlify.app/admin/
```

Click **Login with Netlify Identity**. Enter your credentials. You are in.
